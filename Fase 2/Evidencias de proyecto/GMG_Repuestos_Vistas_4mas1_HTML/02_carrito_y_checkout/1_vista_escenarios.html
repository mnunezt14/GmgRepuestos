Explicación teórica

La vista de escenarios es el "+1" del modelo de Kruchten: no describe una estructura nueva, sino que une y valida las otras cuatro vistas mediante los casos de uso más importantes. Cada escenario muestra qué actor inicia una interacción, qué objetivo persigue y qué funcionalidades del sistema participan, de modo que cualquier decisión tomada en las vistas lógica, de desarrollo, de procesos o física pueda rastrearse hasta una necesidad concreta del usuario.

Nota de notación: Mermaid.js no tiene un diagrama de casos de uso UML nativo, por lo que se emula con flowchart: los actores se dibujan como círculos, los casos de uso como elipses (forma stadium), el límite del sistema como un subgraph y las relaciones «include» / «extend» como flechas punteadas rotuladas.

Explicación técnica aplicada a esta página

El carrito es un panel lateral dentro de index.php gestionado por cart.js, que lo persiste en localStorage (gmg_cart para el carrito y gmg_guardado para "guardar para después"). El cliente puede seleccionar qué ítems pagar, aplicar un código de descuento, ver productos relacionados y, al pagar, completar un formulario con nombre, apellido, RUT, teléfono y correo (GMG no hace despachos, por eso no se pide dirección). checkout.php recalcula los precios desde la base de datos, registra el pedido, envía un correo de aviso al equipo de ventas y crea una preferencia de pago en Mercado Pago, a cuyo formulario se redirige al cliente. El Asistente Virtual también puede iniciar este flujo (checkout guiado).

Diagrama de Casos de Uso

Lectura: el actor principal es el Cliente; el Asistente Virtual actúa como actor secundario porque puede agregar productos y disparar el checkout por el cliente. Pagar con Mercado Pago incluye obligatoriamente la captura y validación de datos, el registro del pedido y la creación de la preferencia; el código de descuento es opcional («extend»). Mercado Pago y el Servidor SMTP son actores de sistema externos, y el Administrador recibe el correo de aviso.
