Explicación teórica

La vista de escenarios es el "+1" del modelo de Kruchten: no describe una estructura nueva, sino que une y valida las otras cuatro vistas mediante los casos de uso más importantes. Cada escenario muestra qué actor inicia una interacción, qué objetivo persigue y qué funcionalidades del sistema participan, de modo que cualquier decisión tomada en las vistas lógica, de desarrollo, de procesos o física pueda rastrearse hasta una necesidad concreta del usuario.

Nota de notación: Mermaid.js no tiene un diagrama de casos de uso UML nativo, por lo que se emula con flowchart: los actores se dibujan como círculos, los casos de uso como elipses (forma stadium), el límite del sistema como un subgraph y las relaciones «include» / «extend» como flechas punteadas rotuladas.

Explicación técnica aplicada a esta página

El Asistente Virtual es un widget flotante presente en la tienda. Atiende consultas en lenguaje natural, por texto, por voz (Web Speech API del navegador) o con hasta 3 fotos de la pieza. Por detrás usa la API de IA de OpenAI (endpoint /v1/responses) con function calling: el modelo no inventa datos, sino que llama a la herramienta buscar_productos, que el servidor ejecuta contra la tabla productos real. El bot puede agregar productos al carrito, iniciar el checkout guiado, ofrecer un aviso de reposición cuando no hay stock y derivar a WhatsApp. Todas las conversaciones quedan guardadas para que el administrador las revise, y el cliente puede calificar cada respuesta.

Diagrama de Casos de Uso

Lectura: el caso central es Consultar repuesto por texto; la voz, las fotos y los chips son formas alternativas de iniciarlo («extend»). Toda consulta incluye el control de límite (15 mensajes por minuto por sesión), la búsqueda en el catálogo real con apoyo de la API IA OpenAI y el guardado de la conversación. A partir de la recomendación, el bot puede extenderse a carrito, checkout o aviso de stock según lo que pida el cliente.
