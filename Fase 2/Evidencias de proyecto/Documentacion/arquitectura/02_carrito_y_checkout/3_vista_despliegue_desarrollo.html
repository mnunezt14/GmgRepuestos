Explicación teórica

La vista de desarrollo (también llamada de implementación o de gestión del software) describe cómo se organiza el código en el entorno de desarrollo: qué módulos, scripts y librerías existen, cómo dependen entre sí y en qué carpetas o capas se agrupan. Es la vista que usan los programadores para repartir trabajo, detectar acoplamientos y gestionar versiones.

Nota de notación: Mermaid no tiene diagramas de componentes ni de paquetes UML nativos; se emulan con flowchart. Los componentes se dibujan con la forma de subrutina [[ ]], los paquetes como subgraph y las dependencias como flechas punteadas rotuladas «use», «require» o «HTTP».

Explicación técnica aplicada a esta página

El módulo reparte responsabilidades en cuatro componentes de servidor. checkout.php está en la raíz del sitio porque Mercado Pago necesita URLs de retorno públicas; validar_codigo.php y relacionados.php son endpoints JSON dentro de backend/, y la capa de correo (email_helpers.php, email_config.php, SmtpMailer.php) está bloqueada por .htaccess para acceso directo. SmtpMailer es un cliente SMTP propio, sin Composer ni PHPMailer, que habla el protocolo directamente por socket. La integración con Mercado Pago se hace con cURL contra la API REST (sin SDK).

Diagrama de Componentes

Lectura: config.php concentra la conexión mysqli y las credenciales de Mercado Pago; es el componente del que dependen todos los demás. Se recomienda mover esas credenciales a variables de entorno o a un archivo fuera de public_html/.
